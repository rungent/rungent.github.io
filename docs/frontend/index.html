Frontend SDK

Consume Rungent streams without adopting a prescribed chat interface.

When state.interaction exists, render text input, choice controls, or approval buttons according to its kind. During an automatic provider retry, the reducer clears incomplete output and keeps the model activity running with retry, maxRetries, and retryReason. Render progress such as “Network interrupted, retrying 1/3…”; no user message is required.

Use failRungentState(state, message) when the HTTP/SSE transport itself throws before a terminal event. Both it and run.failed settle every running model/tool/interaction activity so the UI does not retain stale spinners.

Bounded-loop exhaustion emits run.failed with code=model_step_limit_exceeded, a safe public message, and retryable=true. The SDK exposes these as state.errorCode and state.retryable so products can render localized recovery guidance; the configured numeric limit remains internal.

Cancel an in-flight run or respond by calling await client.cancel(runId), then abort its supplied AbortSignal to close the client stream. The cancel endpoint terminates the active drive and persists a run.cancelled terminal event; using AbortSignal alone cannot reliably notify an HTTP server after the connection disappears. The reducer projects the event as state.status === 'cancelled' rather than conflating it with failure, and replay restores it.

state.activities is an ordered union of model, progress, tool, interaction, and external-task activity. A deferred tool projects state.status === 'waiting_external'; poll persisted events with listEvents(runId, state.lastSeq) while no SSE request is open, and keep cancel available. External task progress updates one stable activity until completion. Progress activity may be running, completed, or failed; repeated events with the same ID update one timeline entry, and terminal events settle a running progress entry. Keep the timeline expanded while running or waiting, keep failures expanded, and collapse it only after state.status === 'completed'. This collapse preference belongs to the product UI, not the SDK. Tool activity exposes only safe message and optional public data; use stable tool names for application-specific labels and icons. Deduplicated non-read calls appear as completed tool activities with deduplicated=true and a safe message; they never execute host business code. Tool activities also expose a stable optional code. Product UIs should hide or localize technical validation failures such as invalid_arguments instead of rendering framework English verbatim.
